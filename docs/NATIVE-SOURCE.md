# Native source provenance and reproduction

OpenBlur tracks the native inputs used by the Android build. Normal Gradle builds compile those tracked files and do not fetch source code.

## Pinned upstream revisions

| Component | Upstream | Commit | Use |
|---|---|---|---|
| MVTools | `https://github.com/dubhater/vapoursynth-mvtools.git` | `17250aa979616ac48dfb0e18abfdcf2bd4e3afc0` | Adapted CPU reference engine; GPL-2.0-or-later |
| VapourSynth | `https://github.com/vapoursynth/vapoursynth.git` | `c5e387f63d7c4ad452bd9e9f57834666dfce6041` | Headers only; LGPL-2.1-or-later notices retained |

These identifiers are declared in both `tools/native/prepare_sources.py` and `app/src/main/cpp/vendor/manifest.json`. The manifest also records SHA-256 hashes of every generated vendor file.

## Tracked source layout

- `app/src/main/cpp/vendor/mvtools/`: copied MVTools source and its `LICENSE`.
- `app/src/main/cpp/vendor/vapoursynth/`: copied VapourSynth headers and `COPYING.LESSER`.
- `app/src/main/cpp/flowblur_kernel.inc`: deterministically extracted from the pinned `MVFlowBlur.cpp`, with its upstream copyright/license preamble.
- `app/src/main/cpp/`: OpenBlur's adaptation, JNI boundary, and build definition.

The current preparation script copies the MVTools source tree without applying an in-place patch. The OpenBlur adaptation is kept outside the vendor tree. The FlowBlur extraction is generated by the explicit transformation in `prepare_sources.py`.

## Refresh or audit the vendor tree

A refresh requires Python 3, Git, and network access. From the repository root:

```bash
python tools/native/prepare_sources.py
```

The script clones missing repositories into ignored `tools/native/upstream/`, checks out the exact detached commits above, copies source and license files, regenerates `flowblur_kernel.inc`, and rewrites `vendor/manifest.json`.

Review the resulting diff. A pin update is a source update and must include the new commit IDs, regenerated manifest, license review, and test evidence.

### Pristine-source and patch rule

Do not make unexplained edits directly in generated `vendor/` files. If an upstream change is required:

1. keep an auditable pristine checkout/archive of the exact pinned revision;
2. store every local change as a tracked patch (or a clearly separated adaptation file);
3. make `prepare_sources.py` apply the patches deterministically;
4. retain upstream copyright and license notices;
5. document patch order, purpose, and affected files here; and
6. regenerate and review `manifest.json`.

At present there is no tracked MVTools patch series. Adding one without updating the preparation process and this document is a release blocker.

## Build and native tests

The Android project declares NDK `25.1.8937393`, CMake `3.22.1`, API 26, C++17, static libc++, and `arm64-v8a`.

```bash
# Build the native library and standalone smoke binary
python tools/native/build_and_test.py

# Build, audit ELF metadata, and run smoke sizes on a device
python tools/native/build_and_test.py --device SERIAL --sizes 128x96 130x98 1920x1080

# Optional AddressSanitizer device run
python tools/native/build_and_test.py --asan --device SERIAL --sizes 128x96 130x98

# Exercise the exact Java/JNI class and methods on ART
python tools/native/test_jni.py SERIAL

# Build through Android Gradle
./gradlew assembleDebug
```

`build_and_test.py` defaults to the Windows SDK location under `%LOCALAPPDATA%/Android/Sdk`. Its direct outputs are ignored under `tools/native/build-*`; Gradle builds compile `app/src/main/cpp/CMakeLists.txt` directly.

## Distribution of corresponding source

An APK containing the adapted MVTools code is object-code distribution under GPL-2.0-or-later. Distributors must satisfy the applicable GPL requirements, including providing complete corresponding source in the preferred form for modification. For this project that includes, at minimum:

- the exact OpenBlur source associated with the binary;
- the exact vendored MVTools source and generated FlowBlur kernel;
- all local patches or adaptation files;
- the VapourSynth headers and retained license notices;
- Gradle/CMake files, wrapper, preparation scripts, and other build-control material; and
- the license texts and notices.

For downloadable releases, publish an immutable source archive/tag alongside the APK and keep equivalent access available. A link to upstream repositories alone is not a substitute for the exact corresponding source of the distributed binary. If using GPLv2 section 3(b)'s written-offer route instead, obtain release-specific legal review and preserve the offer for the required term.

This document records engineering provenance; it is not legal advice.
